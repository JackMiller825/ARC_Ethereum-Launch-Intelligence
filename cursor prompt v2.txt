# 4. Reliable Ethereum indexing engine

Improve the existing ingestion architecture.

Requirements:

- Discover every relevant V2/V3/V4 pool supported by the implementation.
- Use protocol-specific event decoding.
- Support pool creation, liquidity initialization and subsequent trading.
- Use block timestamps and exact transaction/log ordering.
- Deduplicate events by stable chain/transaction/log identifiers.
- Handle blockchain reorganizations.
- Support historical backfills.
- Support incremental live updates.
- Persist indexing checkpoints.
- Resume interrupted indexing.
- Implement retry logic with bounded exponential backoff.
- Respect RPC rate limits.
- Adaptively split oversized `eth_getLogs` requests.
- Avoid requesting the same block range repeatedly.
- Detect incomplete index coverage.
- Reconcile results from multiple providers when necessary.
- Prevent race conditions when users switch tokens or time ranges.

Use integer-safe handling for all raw token amounts.

Build a canonical trade reconstruction layer that distinguishes actual swaps from ERC-20 transfers, liquidity operations, deposits, approvals and failed transactions.

For multihop routes, count each economic token acquisition once.

Track ETH/WETH consideration separately from stablecoin and other quote assets.

If a route cannot be valued reliably in ETH, do not invent the value. Preserve it in an unvalued or unsupported category.
